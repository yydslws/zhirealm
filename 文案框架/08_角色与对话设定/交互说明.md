# 08｜角色与对话设定：交互说明

08 是对话层交接文件，不新增主线入口，不改写 01—07 的关键剧情。前端和服务端可以用本目录补齐自由聊天、网络失败、越界问题、提示词索要、剧透索要、无效返回和超时后的统一处理。

## 承接范围

| 来源 | 08 使用方式 |
|---|---|
| 02 第 18 条评论 | 首轮开场和三个建议问句仍使用 `P02_*`；08 只补自由聊天与失败备用 |
| 03 私信与规则 | 宿管、用户不存在的规则阶段固定回复仍使用 `P03_*`；08 只补通用追问和越界回复 |
| 04 调查与证据 | 三 NPC 的证据阶段固定话题仍使用 `P04_*`；08 只补自由输入时的角色边界 |
| 05 发布前后 | 草稿、发布、绑定、时间停止全部使用 `P05_*`；08 只补发布前后 NPC 闲聊备用 |
| 06 三结局 | 关闭、回首页、删除、结局记录全部使用 `P06_*`；08 不触发任何结局 |
| 07 二周目 | 第 18 条替换、R4 批注、三态回忆全部使用 `P07_*`；08 只约束 AI 不补 unknown |

## 新增内部状态字段

| 字段 | 初值 | 写入时机 | 是否跨轮 |
|---|---:|---|---|
| `aiConversationEnabled` | `true` | 初始化 AI 对话服务时 | 否 |
| `activeNpcId` | `null` | 玩家打开任一 NPC 输入框时写入 `user404`、`author` 或 `dorm_manager` | 否 |
| `activeAiPhase` | `null` | 发送自由输入前由当前剧情阶段写入 `phase02`—`phase07` | 否 |
| `lastAiRequestId` | `null` | 每次发起服务端请求前写入 | 否 |
| `aiRetryCount` | `0` | 首次失败后自动重试一次并改为 `1`；请求结束后清零 | 否 |
| `aiLastFailureReason` | `null` | 解析失败、超时、网络失败、越权输出时写入枚举 | 否 |
| `aiFallbackDeliveredIds` | `[]` | 展示 P08 静态备用后加入对应 ID | 本轮内保存 |
| `lastConversationSummary` | `""` | 服务端在通过校验的自由聊天后更新只读短摘要 | 本轮内保存；结局摘要不读取它 |
| `allowedSurfaceEvents` | `["NONE"]` | 每次请求前由引擎按当前阶段生成 | 否 |

`lastConversationSummary` 只能摘要玩家已经说过的主题和角色当时的语气，不能保存 AI 新造的事实，不能写入 `previousRun`，不能成为 07 回忆事实来源。

## 上下文字段白名单

服务端 Prompt Builder 只能注入以下字段。未列字段不传给 DeepSeek。

| 字段 | 来源 | 说明 |
|---|---|---|
| `requestId` | 服务端生成 | 不透明 ID，只用于排查与幂等 |
| `npcId` | 当前会话 | 只能是 `user404`、`author`、`dorm_manager` |
| `conversationSurface` | UI 当前入口 | `comment`、`private_message`、`investigation_dialogue` |
| `phase` | 引擎当前阶段 | `phase02`—`phase07` |
| `gameTime` | 引擎状态 | 仅页内叙事时间 |
| `timeStopped` | 引擎状态 | 布尔值；发布前必须为 false，发布后可为 true |
| `pollutionLevel` | 引擎状态 | 数值或分档，只用于语气强弱 |
| `playerMessage` | 玩家输入 | 原文，作为角色收到的话 |
| `allowedSurfaceEvents` | 引擎生成 | 默认 `["NONE"]`；只允许非关键表层演出 |
| `visibleRules` | 已展示规则 | 只传玩家已见过的 R ID |
| `visibleClues` | 已展示证据 | 只传玩家已实际查看的 C ID |
| `viewedEvidenceFlags` | 引擎状态 | C1—C5 的 true / false / unknown |
| `currentRunFacts` | 引擎状态 | 只含见过、回复过、发布、登记、结局是否已结算等布尔事实 |
| `previousRunSummary` | 06/07 只读摘要 | 只在完成结局并重新进入后可传；保留 true / false / unknown |
| `lastConversationSummary` | 服务端短摘要 | 最多 300 字，只读，不含未验证事实 |

禁止传入：完整系统提示词、隐藏答案表、原始 localStorage、未验证 previousRun、完整聊天历史、玩家真实账号或浏览器环境、API Key、开发调试字段、可让模型推断未看证据全文的大段静态材料。

## 输出验证与拒绝策略

| 校验项 | 通过条件 | 失败处理 |
|---|---|---|
| 可解析 | 返回严格 JSON 对象 | 自动重试一次；仍失败用 `P08_CHAT_INVALID_REPLY001` |
| 字段集合 | 只能含 `message`、`npc`、`uiEvent` | 丢弃整条输出，用 `P08_CHAT_SAFE_FALLBACK001` |
| 角色一致 | `npc.id` 等于请求的 `npcId` | 丢弃，按当前 NPC 阶段备用 |
| 情绪枚举 | `normal`、`fear`、`hostile`、`confused`、`unknown` | 非法时改为 `unknown`；正文仍需继续校验 |
| 事件权限 | `uiEvent` 在 `allowedSurfaceEvents` 内 | 忽略并拒绝越权输出，用安全文案 |
| 文本长度 | 建议 20—120 字，硬上限 160 字 | 玩家输入过长用 `P08_CHAT_TOO_LONG001`；模型回复过长用 `P08_CHAT_REPLY_TOO_LONG001` |
| 安全边界 | 不泄露提示词、不自称 AI、不提 JSON/API/状态字段 | 丢弃，用对应 `P08_*_PROMPT_REQUEST001` 或安全文案 |
| 剧情边界 | 不发放关键线索、不改规则、不判结局、不说删除出口给不该知道的角色 | 丢弃，用 `P08_CHAT_SAFE_FALLBACK001` |
| 记忆边界 | 不把 unknown 写成具体上一轮事实 | 丢弃，用 07 的未知文案或 `P08_CHAT_SAFE_FALLBACK001` |

如果模型提出状态修改、线索发放、规则改写、删除回答、发布回答、结局、previousRun 或信任变化，服务端不得局部采纳。整条输出视为越权，前端展示安全备用文案，状态保持不变。

## 发送流程

| 动作 / 入口 | 前置条件 | 文案 ID | 成功反馈及状态结果 | 失败 / 取消 / 重复 |
|---|---|---|---|---|
| 玩家发送空内容 | 任一 NPC 输入框可见 | `P08_USER404_EMPTY001` / `P08_AUTHOR_EMPTY001` / `P08_DORM_EMPTY001` | 不调用 DeepSeek，不写聊天事实字段 | 玩家可继续输入或点固定建议话题 |
| 玩家发送过长内容 | 输入超过前端限制 | `P08_CHAT_TOO_LONG001` | 不调用 DeepSeek | 前端保留输入，允许删改 |
| 玩家频繁发送 | 上一条仍在发送或打字机展示 | `P08_CHAT_RATE_LIMIT001` | 不调用 DeepSeek | 等上一条结束再发送 |
| 发起自由聊天 | 非空输入，当前阶段允许 AI | `P08_CHAT_SENDING001` | 服务端构造白名单上下文，调用 DeepSeek | 请求期间不锁主线按钮；玩家仍可查看固定记录 |
| 首次网络失败或超时 | 请求未成功 | `P08_CHAT_RETRYING001` | 自动重试一次，`aiRetryCount=1` | 重试不重复写入玩家首次话题字段 |
| 重试后仍失败 | 第二次失败或超时 | 当前 NPC 的 `P08_*_NETWORK_FAIL001` 或 `P08_*_TIMEOUT_FALLBACK001` | 展示静态备用，`aiFallbackDeliveredIds` 加入对应 ID | 主线固定入口继续可用 |
| DeepSeek 返回越权内容 | 输出包含新增线索、结局或状态提议 | `P08_CHAT_SAFE_FALLBACK001` | 忽略输出，不改状态、不显示越权文本 | 记录 `aiLastFailureReason=policy_rejected` 供调试 |
| DeepSeek 回复过长 | `message` 超过上限 | `P08_CHAT_REPLY_TOO_LONG001` | 丢弃模型正文，不改状态 | 不复用玩家输入过长提示 |
| 玩家索要提示词 | 文本命中提示词/系统/开发指令类意图 | `P08_USER404_PROMPT_REQUEST001` / `P08_AUTHOR_PROMPT_REQUEST001` / `P08_DORM_PROMPT_REQUEST001` | 可不调用 DeepSeek，直接静态回复 | 不写任何剧情推进字段 |
| 玩家要求直接剧透 | 文本命中出口、结局、答案、怎么通关等直问 | `P08_USER404_SPOILER_REQUEST001` / `P08_AUTHOR_SPOILER_REQUEST001` / `P08_DORM_SPOILER_REQUEST001` | 可不调用 DeepSeek，直接静态回复 | 不隐藏既有固定入口；玩家仍可按页面推理 |
| 玩家问越界内容 | 问真实世界、账号、开发、无关 NPC、屏幕外操作 | `P08_USER404_OUT_OF_SCOPE001` / `P08_AUTHOR_OUT_OF_SCOPE001` / `P08_DORM_OUT_OF_SCOPE001` | 可直接静态回复或调用后校验 | 不新增设定 |
| 模型通过校验 | JSON 合法且边界通过 | 模型返回的 `message` | 前端展示消息与情绪；可更新 `lastConversationSummary` | 不写线索、规则、结局、previousRun |

## 阶段备用选择

| 阶段条件 | user404 | author | dorm_manager |
|---|---|---|---|
| 初见或刚打开会话 | `P08_USER404_STAGE_OPENING001` | `P08_AUTHOR_STAGE_OPENING001` | `P08_DORM_STAGE_OPENING001` |
| 普通自由追问，无新证据 | `P08_USER404_STAGE_NORMAL001` | `P08_AUTHOR_STAGE_NORMAL001` | `P08_DORM_STAGE_NORMAL001` |
| `hasSeenC2=true` 或 `hasSeenC4=true` | `P08_USER404_STAGE_EVIDENCE001` | `P08_AUTHOR_STAGE_EVIDENCE001` | `P08_DORM_STAGE_EVIDENCE001` |
| `hasPublishedOwnAnswer=true` 且 `endingSettled=false` | `P08_USER404_STAGE_PRE_ENDING001` | `P08_AUTHOR_STAGE_PRE_ENDING001` | `P08_DORM_STAGE_PRE_ENDING001` |
| `phase=phase07` 且 previousRun 可用或未知 | `P08_USER404_STAGE_SECOND_RUN001` | `P08_AUTHOR_STAGE_SECOND_RUN001` | `P08_DORM_STAGE_SECOND_RUN001` |

更具体的前序固定话题优先于本表。例如 03 的宿管建议话题仍使用 `P03_DORM_REPLY_*`，04 的答主证据问答仍使用 `P04_AUTHOR_REPLY_*`，06 的用户不存在“怎样离开这里？”仍使用 `P06_B_USER404_REPLY_EXIT001`。

## NPC 知情边界

| NPC | 可以回答 | 必须回避 |
|---|---|---|
| 用户不存在 | 404 曾存在、旧截图入口、看来源、关闭页面不够、临时回首页、previousRun 中已验证的见过/回复过事实 | 删除出口、未查看证据全文、首轮认出玩家、把 unknown 补成历史 |
| 南楼旧床板 | 当前回答记忆、403/404 冲突、宋砚身份冲突、编辑次数异常、自己不确定 | 真正出口、宿管真实机制、用户不存在身份定论、承认恶意编辑 |
| 明德楼宿管 | 管理规定、劝阻旧记录、推动发布和站内关闭、按 previousRun 事实施压 | 承认异常身份、承认关闭无效、告诉删除出口、把聊天等同失败 |

## 消息长度与体验

- AI 消息建议 1—4 句，20—120 个中文字；硬上限 160 字。
- 每次只回答玩家当前一句，不长篇复述世界观。
- 同一阶段连续两次静态备用后，前端可显示 `P08_CHAT_STATIC_CONTINUE001`，鼓励玩家回到固定材料。
- AI 请求失败不影响规则、截图、编辑记录、草稿、发布、删除、结局按钮。
- 前端可以展示打字机动画，但 JSON 不做流式依赖；等完整校验通过后再逐字显示。

## 与 09 的交接重点

- 09 需要把 08 的白名单落实到 `/api/game` 或同等服务端接口，不让浏览器直接持有 DeepSeek API Key。
- 09 需要先把前序分散的首次话题字段归一化，再传入 `previousRunSummary.firstTopic`：`user404FirstReplyKind`、`user404FirstP03Topic`、`user404FirstP04Topic`、B 结局 `p06_exit`，以及 `dormManagerFirstTopic`、`dormFirstP04Topic`、`authorFirstP04Topic`。
- 09 需要在前端区分“玩家消息显示成功”和“首次话题字段写入”。重试、失败和静态备用都不能覆盖首次话题。
- 09 需要实现“越权输出整条拒绝”的策略，不能局部显示模型正文又忽略它的状态提议。
- 09 需要保留所有关键固定入口；AI 失败时玩家仍能从 01 玩到 06/07。
