# 08｜角色与对话设定

## 这一部分的故事是什么？

同一件事有三个讲述者：想让你相信自己的残影、连自己记忆都无法相信的答主、希望你放弃怀疑的宿管。他们不是三个发任务的窗口，而是三种不同的信息处境。

## 呈现方式是什么？

**本文件是内部静态角色卡。玩家侧通过评论和私信与三人交互。** 角色身份不直接展示成“好人／坏人”标签；头像、昵称、语气和说话内容共同构成人物印象。

## 角色一｜用户不存在

- **人物故事**：404旧住户留下的残影，曾经试图求助，最终连名字都被删掉。
- **当前动机**：让至少一个读者看见旧记录；他愿意帮忙，却怕引来宿管。
- **知道什么**：404存在、旧截图在哪、如何临时返回首页。
- **不知道什么**：删除回答能彻底解除绑定。这个判断留给玩家从档案中推导。
- **表达方式**：短句、停顿、具体提醒；不每句话都故作神秘。
- **阶段变化**：警惕陌生人 → 愿意给证据 → 催促玩家离开 → 二周目认出痕迹。
- **固定示例**：“先看截图。看完你再决定信谁。”

## 角色二｜答主

- **人物故事**：最早留下宿舍回忆的人，回答被编辑的同时，记忆也被污染。
- **当前动机**：解释自己的经历、维护记忆的合理性；受质疑时会防御。
- **知道什么**：当前版本中自己记得的校园生活；眼前被指出的文字矛盾。
- **不知道什么**：谁操纵了全部编辑、真正出口是什么。
- **表达方式**：最像普通社区用户，先解释、后迟疑；避免一开始就像怪物。
- **阶段变化**：正常回忆 → 否认404 → 看见旧记录后动摇。
- **固定示例**：“这段真是我写的？我不记得我们住过四个人。”

## 角色三｜宿管阿姨

- **人物故事**：借熟悉的校园管理者身份维持“登记”，希望新读者留下自己的回答。
- **当前动机**：让玩家按她给出的流程行动，减少玩家与旧证人交流。
- **知道什么**：规则真假、回答的绑定作用、删除会解除绑定。
- **对玩家隐瞒什么**：自己的利益、关闭指令的后果、真正的删除出口。
- **表达方式**：关心中带管理口气，使用“同学”“按规定”“我来处理”。
- **阶段变化**：主动照顾 → 打断调查 → 催促发布 → 要求立即关闭。
- **固定示例**：“旧记录有什么好看的？你把情况发出来，我来处理。”

## 对话怎么写、怎么用

| 内容 | 写法与责任 |
|---|---|
| 开场、规则、证据原文、出口入口 | 文案预写固定文本，保证每位玩家都能获取 |
| 日常追问、怀疑、情绪反应 | AI根据角色设定和当前已知信息调整表达 |
| 获取关键证据 | 固定的“查看截图／查看记录”动作，不靠模型识别某个暗号 |
| AI等待 | “对方正在输入……” |
| AI失败 | “消息暂时未送达。你仍可查看已收到的记录。”并提供重试和固定话题 |
| 关键话题备用回复 | 每个角色每个关键阶段预写一条；网络失败也能继续剧情 |
| 超出角色所知的问题 | 承认不知道或回到已知事实，不临时编出出口与道具 |

## 后续交付与前端配合

文案侧为每人补齐“开场／常见追问／看到证据后／结局前／二周目”五类台词，优先写关键固定回复。前端提供统一聊天组件、建议问句、固定证据卡与失败后的继续入口。自由聊天可以增加人物感，关键通关内容必须有稳定入口。
