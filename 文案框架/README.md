## 玩家实际经历的顺序

| 部分 | 这一段要讲的故事 | 呈现方式 | 玩家心里应当出现的问题 |
|---|---|---|---|
| 01 正常阅读 | 某栋宿舍楼从403直接跳到405，大家却都觉得正常 | 问题、长回答、普通评论；静态阅读 | 为什么没有404？ |
| 02 第十八条评论 | 玩家点开一条不该存在的评论，里面的人正在等读者 | 展开评论、数字变化、首次回复 | 他是在跟我说话吗？ |
| 03 私信与规则 | 宿管主动提供帮助，却要求玩家远离另一位证人 | 私信聊天、规则卡、通知 | 谁才是在保护我？ |
| 04 调查与证据 | 旧截图和编辑记录证明，这个网页在不断改写人的存在 | 点击查看证据、询问NPC、对照文本 | 我该相信证据还是身份？ |
| 05 你成为了回答 | 玩家发现网页已经把刚才的操作写成自己的经历 | 查看草稿、确认发布、正文替换 | 我什么时候成了故事里的人？ |
| 06 三个结局 | 同一组证据，可以让人被留下、暂时离开，或解除与帖子的绑定 | 在网页原有控件上执行不同动作 | 到底什么才算离开？ |
| 07 二周目记忆 | 再次进入时，角色记得玩家上次如何选择 | 已有页面换文案、NPC回忆、旧记录 | 为什么只有我以为一切重置了？ |

01—07是一条体验线，并不要求前端做七个页面。主体始终是同一个问答页，用评论展开区、私信侧栏、记录弹层和结局状态承载变化。

## 文案与前端如何分工

- **你负责**：故事事实、问题与回答、评论、规则、证据、角色口吻、关键固定台词、按钮与结局文字。
- **前端同学负责**：这些内容出现在哪里、何时出现、如何点击、如何变化，以及记录玩家已经做过什么。
- **共同对齐**：所有关键操作的触发条件，尤其是发布回答、删除回答与二周目记忆。

建议先看 [00 故事总纲](00_故事总纲/README.md)，再顺着01—07读故事。搭页面时直接对照 [09 前端交接总表](09_前端交接/前端交接总表.md)。

## 本稿补齐的三处剧情连接

1. **先有自己的回答，才能删除自己的回答。** 第05部分加入“页面生成草稿—玩家确认发布—回答绑定身份”的过程。
2. **区分普通离开与真正解除绑定。** 普通结局B只是离开当前页面，帖子里仍留有玩家的回答；隐藏结局C删除该回答，解除本轮绑定。
3. **二周目台词必须对应实际经历。** 没见过某角色、没相信宿管或没有死亡的玩家，不会被统一套用“你上次就是这么死的”。

原技术文档保持原样。本次交付只完成文案与交互说明，没有编写前端、接入接口或部署应用。
