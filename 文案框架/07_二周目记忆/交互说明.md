# 07｜二周目记忆：交互说明

本阶段承接 06 的“重新进入”。07 不新增独立剧情页，而是在同一个问答页上替换少量文字：第 18 条评论开场、R4 下方批注、三位 NPC 的回访态度、上一轮回答痕迹和清除记录流程。核心原则是只引用上一完整轮的可验证事实，不用 `run>=2`、AI 闲聊或旧草稿推断历史。

## 进入条件

| 入口 | 前置条件 | 结果 | 取消 / 重复 / 返回行为 |
|---|---|---|---|
| 06 第三屏点击 `P06_CTRL_REENTER001` | `endingSettled=true` 且 `endingScreenIndex=3` 且 `readyForNextRun=true` | `run=run+1`，进入 07，展示 `P07_REENTRY_NOTICE001` 与符合条件的替换文案 | 只有这一动作增加周目；刷新结局页只恢复结局屏 |
| 真实刷新或重新打开标签 | 任意未点击“重新进入”的状态 | 展示前序对应恢复文案，可在 06 使用 `P06_REAL_CLOSE_RESUME001`，07 可用 `P07_RESUME_CURRENT_RUN001` | 不增加周目，不写 `previousRun`，不清空本轮状态 |
| 存在旧 `run>=2` 但无完整 `previousRun.completed=true` | 旧存档缺失或不一致 | 展示 `P07_FIRST_RUN_FALLBACK001` 或 `P07_MEMORY_SUMMARY_UNKNOWN001` | 不套用二周目回忆；玩家按当前轮继续 |

07 启动时必须先复制并锁定上一完整轮摘要为 `p07LoadedPreviousRun`，再清空当前轮临时状态。不要在新轮进行中用当前轮字段覆盖 `previousRun`；下一次覆盖只能发生在新轮再次完成结局时。

同时保留 `previousRun` 与 `p07LoadedPreviousRun`。A/B 的旧回答可以作为上一轮痕迹显示，不能变成当前轮已发布回答；C 的旧回答已删除，不能从任何摘要、草稿或快照恢复正文。

## `previousRun` 有效性判定

| 情况 | 判定 | 可用文案 |
|---|---|---|
| `previousRun.completed=true` 且 `endingId` 与 `endingEventId` 匹配 | `valid` | 正常套用 A/B/C、见过/没见过、NPC 态度 |
| 无 `previousRun`、读取失败或 `completed` 缺失 | `missing` 或 `load_failed` | `P07_FIRST_RUN_FALLBACK001`、`P07_STORAGE_LOAD_FAIL001`、`P07_MEMORY_SUMMARY_UNKNOWN001` |
| `endingId` 与动作布尔值冲突，如 `delete` 但 `usedOwnAnswerDelete=false` | `inconsistent` | `P07_ENDING_MEMORY_INCONSISTENT001`、`P07_MEMORY_BADGE_UNKNOWN001` |
| 字段存在且值为 `false` | 明确未发生 | 使用“没见过”“未回复”“未交谈”文案 |
| 字段缺失、旧枚举不认识、存储值不是布尔值 | `unknown` | 使用对应未知文案，不补事实 |

`false` 和 `unknown` 必须分开。`false` 可以写“没有回复”“没有问答主”；`unknown` 只能写“记录不完整”“无法确认”。

## 替换位置与选择优先级

| 替换位置 | 选择顺序 | 文案 ID | 状态结果 |
|---|---|---|---|
| 重新进入顶部提示 | `p07MemoryIntegrity=valid` → `missing/load_failed` | `P07_REENTRY_NOTICE001`、`P07_MEMORY_BADGE001`；失败时用 `P07_FIRST_RUN_FALLBACK001` 或 `P07_STORAGE_LOAD_FAIL001` | 不改变剧情，只提示记忆状态 |
| 第 18 条评论首句 | `metUser404Seen=true` → `false` → `unknown` | `P07_COMMENT18_SEEN001` / `P07_COMMENT18_NOT_SEEN001` / `P07_COMMENT18_UNKNOWN001` | 替换 02 的 `P02_COMMENT018_TEXT001`，仍在第 18 条位置 |
| 第 18 条评论补充回忆 | `user404Replied=true` 按首次话题细分 → `false` → `unknown` | `P07_COMMENT18_REPLIED_*` / `P07_COMMENT18_NOT_REPLIED001` / `P07_COMMENT18_REPLIED_UNKNOWN001` | 只在第 18 条展开后出现，不提前发放线索 |
| R4 下方批注 | 有 C2/C4/C5 或结局有效 → 旧记录不足 | `P07_RULE_R4_NOTE001` / `P07_RULE_R4_NOTE_UNKNOWN001` | 追加在 `P03_RULE_R4_TEXT001` 下方；不改原规则、不改真假 |
| 结局回忆 | A → B → C → 不一致/未知 | `P07_ENDING_MEMORY_A001` / `P07_ENDING_MEMORY_B001` / `P07_ENDING_MEMORY_C001` / `P07_ENDING_MEMORY_INCONSISTENT001` / `P07_ENDING_MEMORY_UNKNOWN001` | 展示在上一轮记录区或 NPC 回访旁；三者互斥 |
| 上一轮回答痕迹 | A 保留不可见 → B 保留可见且有自动评论 → C 已删除 | `P07_A_RETAINED_PLACEHOLDER001` / `P07_B_RETAINED_PLACEHOLDER001` + `P07_B_RESIDUAL_COMMENT001` / `P07_C_DELETED_PLACEHOLDER001` | 只作为旧痕迹，不设置当前轮 `hasPublishedOwnAnswer` |
| 清除记录 | 点击入口 → 确认/取消/失败 | `P07_CLEAR_RECORDS_*` | 清除成功后不再套用二周目替换；取消不改记录 |

如果同一位置同时满足多个条件，以“有效结局事件”优先于普通行为摘要，以 `true` 优先于 `false`，以明确 `unknown` 优先于根据缺失字段猜测。B 的自动评论只在 `previousRun.endingId=exit` 且 `bAutoCommentAdded=true` 时显示；它不计入玩家消息，不作为 `user404Replied` 的来源。

## 三位 NPC 回访

| NPC | 出现条件 | 优先级 | 文案 ID | 知情边界 |
|---|---|---|---|---|
| 用户不存在 | 第 18 条评论可见 | 结局 A/B/C 优先，其次见过/回复过状态 | `P07_USER404_ATTITUDE_A001` / `P07_USER404_ATTITUDE_B001` / `P07_USER404_ATTITUDE_C001` / `P07_USER404_ATTITUDE_UNKNOWN001` | 知道玩家是否在记录里、是否回首页；不知道删除出口的原理，C 只能说记得有人删过 |
| 宿管 | 宿管私信再次出现 | 结局 A/B/C 优先，其次未知 | `P07_DORM_ATTITUDE_A001` / `P07_DORM_ATTITUDE_B001` / `P07_DORM_ATTITUDE_C001` / `P07_DORM_ATTITUDE_UNKNOWN001` | 继续维护管理规定口吻；不能把未确认关闭写成 A，不能说真实浏览器关闭有效 |
| 答主 | 04 询问入口再次打开 | `hasAskedAuthorInP04` 与 `firstTopic.author` | `P07_AUTHOR_ATTITUDE_*`、`P07_AUTHOR_TOPIC_*` | 只表现被污染的记忆和编辑记录冲突；不能突然知道删除出口或认定宋砚等于用户不存在 |

同一 NPC 每次回访只拼接一条态度句和至多一条首次话题句。不要同时显示 A/B/C 三种态度，也不要同时显示“你上次问过我”和“你上次没有问我”。

## 清除记录

| 动作 / 入口 | 前置条件 | 文案 ID | 成功反馈及状态结果 | 取消 / 重复 / 返回行为 |
|---|---|---|---|---|
| 点击清除记录 | 07 中任意可操作状态 | `P07_CLEAR_RECORDS_ENTRY001`、`P07_CLEAR_RECORDS_CONFIRM_TITLE001`、`P07_CLEAR_RECORDS_CONFIRM_BODY001`、`P07_CTRL_CLEAR_CONFIRM001`、`P07_CTRL_CLEAR_CANCEL001` | `p07ClearConfirmOpen=true` | 打开确认框不清除、不重置当前轮 |
| 取消清除 | `p07ClearConfirmOpen=true` | `P07_CLEAR_RECORDS_CANCEL_TOAST001` | `p07ClearConfirmOpen=false`，保留 `previousRun` 和当前替换 | 可再次打开 |
| 确认清除成功 | `p07ClearConfirmOpen=true` 且本地存储删除成功 | `P07_CLEAR_RECORDS_SUCCESS_TOAST001` | `previousRun=null`，`p07LoadedPreviousRun=null`，`p07MemoryIntegrity=missing`，`p07MemoryCleared=true`，`p07ReplacementAppliedIds=[]`；立即移除已应用替换并恢复首轮原文，后续按首次进入展示；不恢复 C 删除的旧回答正文 | 重复确认只显示已清除后的首次入口 |
| 确认清除失败 | 本地存储删除失败 | `P07_CLEAR_RECORDS_FAIL_TOAST001`、可追加 `P07_STORAGE_SAVE_FAIL001` | 不删除内存中的当前展示；`p07StorageStatus=clear_failed` | 玩家可继续阅读或稍后重试 |

清除记录只处理跨周目记忆。它不是游戏内“删除回答”动作，不能替代 C 结局；如果上一轮 C 已删除回答，清除记录也不能恢复已删除正文。

## AI 与断网约束

- 07 的关键替换全部使用固定文案，断网可读。
- AI 可用于三位 NPC 的自由闲聊语气，但只能围绕已选择的固定事实表达；不能写入新 `previousRun`，不能判定玩家上次信任谁，不能宣布死亡，不能恢复 C 的已删除回答。
- AI 失败时分别使用 `P07_AI_FALLBACK_USER404001`、`P07_AI_FALLBACK_DORM001`、`P07_AI_FALLBACK_AUTHOR001`。
- 存储失败时显示 `P07_STORAGE_LOAD_FAIL001` 或 `P07_STORAGE_SAVE_FAIL001`，并采用中性降级，不阻塞当前轮阅读。

## 前端呈现要求

- 07 复用 01–06 的问答页、评论区、规则面板、私信侧栏、调查询问入口，不新增第二套页面。
- 至少三个替换位置必须明显可见：第 18 条评论首句、R4 下方批注、一个 NPC 回访或上一轮记录区。若上一轮为 B，再显示残留自动评论；若上一轮为 C，只显示已删除占位。
- 玩家可见正文不要显示字段名、开发 ID 或测试说明。
- 新轮再次发布回答时生成新的 `ownAnswerId` 和 `ownAnswerRunId=run`。上一轮 A/B 残留回答只作为痕迹，C 不可恢复正文。
- 07 不实际实现存储；本文件只定义文案和交互条件，09 可据此落到前端存储与恢复。

## 总控验收补充：首次话题归一化

先读取previousRun.user404Replied。为false时只用P07_COMMENT18_NOT_REPLIED001；为unknown时只用P07_COMMENT18_REPLIED_UNKNOWN001；为true时才解析话题。话题优先取firstTopic.user404的已知非null值；若为null，再依次查firstTopic.user404P03、firstTopic.user404P04以及已结算B的p06_exit。P03值old_screenshot/dorm_manager/dangerous_rule，P04值screenshot/c5_entry/exit，分别映射到截图类、出口/旧评论类；仍无已知值时使用回复内容未知，绝不能用未回复文案。

答主同理：hasAskedAuthorInP04=false才使用未问；true而话题null/缺失时使用话题未知，不使用未交谈。清除来访记录只清跨轮摘要与对应替换，不修改当前轮已经获得的线索、草稿或发布状态，也不改变run；若已进入二周目，当前轮继续进行。
