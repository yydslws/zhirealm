# 09｜前端交接：每段故事落在哪里

## 这一部分的故事是什么？

这是整个故事的页面调度表：同一张看起来普通的问答网页，随着玩家阅读和操作，依次变成现场、证据库、登记表和出口。

## 呈现方式是什么？

**内部静态交付表。** 前端据此搭骨架，文案据此填内容。01—07代表叙事阶段，角色对话、证据弹层与规则面板可以跨阶段反复打开。

## 页面与内容对应

| 文件夹 | 页面位置／组件 | 文案提供 | 前端提供 |
|---|---|---|---|
| 01 正常阅读 | 问题头部、回答卡、评论区 | 标题、回答、普通评论 | 排版、展开、阅读位置触发 |
| 02 第十八条评论 | 折叠评论、回复区 | 警告、异常评论、首次回复 | 17→18、插入评论、输入框 |
| 03 私信与规则 | 私信侧栏、规则卡、消息详情 | NPC消息、规则原文、时间标签 | 通知、角色切换、规则来源回看 |
| 04 调查与证据 | 截图卡、编辑记录、答主对话 | 五条证据与五次版本短句 | 查看、记录已读、重访 |
| 05 你成为了回答 | 我的草稿、我的回答卡 | 草稿片段、发布回执、催促 | 按行为拼文、发布、更多菜单 |
| 06 三个结局 | 站内关闭、返回首页、删除回答 | 操作提示、确认框、结局短句 | 条件判断、取消、结算 |
| 07 二周目记忆 | 复用评论、规则、私信 | 按上一轮经历变化的台词 | 保存与读取真实行为 |
| 08 角色设定 | 三个角色的评论／聊天 | 角色卡、固定回复与备用文本 | 统一对话组件、固定话题入口 |

## 关键触发约定

| 条件／动作 | 呈现的变化 | 下一步入口 |
|---|---|---|
| 读到评论区 | 故事时间进入02:00，17变18 | 展开折叠评论 |
| 首次展开 | 用户不存在出现，轻度异常 | 回复／查看新私信 |
| 宿管私信出现 | 规则卡与信息矛盾 | 看规则、查时间、查看旧截图 |
| 查看C2或C4 | 证据留存，出现“我的草稿” | 继续调查／查看草稿 |
| 发布自己的回答 | 出现“已登记”，时间停止，强度提高 | 三种结局操作；仍可调查 |
| 执行某个结局动作 | 结局成立，一次性写入本轮结果 | 重新进入 |
| 结局后重新进入 | 增加周目，载入对应回忆文本 | 原主线继续 |

## 异常演出只做三组主效果

1. **数量变化**：17变18，让玩家第一次察觉异常。
2. **文本变化**：回答与称呼逐步改写，让玩家确认记录正在被操纵。旧版本可以回看。
3. **时间停止与身份登记**：发布后时钟停住、署名“你”的回答出现，让威胁落到自己身上。

每种效果都服务一处故事变化。关键按钮、证据和退出游戏的真实浏览器操作不因演出被阻断。

## 后续每条文案使用的交付格式

```text
文案编号：FOLD_001
所属部分：02_第十八条评论
页面位置：折叠评论中的第18条
出现条件：首轮首次展开折叠评论
说话者：用户不存在
展示正文：你终于点进来了。
呈现方式：点击后插入，短暂逐字出现
玩家可做：回复／回到正文／查看私信
触发结果：记录已见用户不存在，展示私信通知
是否允许AI改写：否
二周目版本：根据是否见过角色选择另一条文案
```

文案编号用于双方指认同一条内容，避免用“那个弹窗里的第二句话”沟通。首版用Markdown协作即可，确定全文后再按前端的数据结构转换。
