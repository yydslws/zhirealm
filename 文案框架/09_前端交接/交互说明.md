# 09｜前端交接：交互说明

## 使用顺序

1. 加载并迁移存档，先恢复当前轮，再渲染页面。
2. 根据 `scene`、阶段开放字段和已读集合决定组件；文案正文只按 ID 读取。
3. 玩家操作先校验前置状态，再以单次事务写入结果；成功后演出，失败时不写半成品状态。
4. 自由对话失败时退回 08 的固定回复和固定话题。关键剧情始终可以离线推进。
5. 结局只在 A/B/C 的确认操作成功提交后成立；刷新、真实关闭标签页、聊天和阅读都不结算。

## 通用事务约定

| 场景 | 写入顺序 | 失败处理 |
|---|---|---|
| 第 18 条首次展开 | 锁定动作→插入一次→写已见与污染→释放锁 | 恢复 17/18 的已提交版本，不生成第二条评论 |
| 发布回答 | 冻结草稿快照→创建唯一回答→登记→停钟→开放 06 | 任一步失败则整体回滚，显示 `P05_PUBLISH_INCOMPLETE_TOAST001` |
| A/B/C 结局 | 校验本轮回答→加 `endingActionLock`→一次性写结局与 `previousRun`→进入第 1 屏 | 整体回滚并释放锁；分别显示 `P09_CLOSE_COMMIT_FAILED001`、`P09_HOME_COMMIT_FAILED001` 或 `P09_DELETE_COMMIT_FAILED001` |
| 重新进入 | 校验第 3 屏→锁定上一轮摘要→`run+1`→重置当前轮→加载 07 差异文案 | 保持原结局第 3 屏，显示 `P09_REENTER_FAILED001` |
| 清除上一轮记录 | 删除 `previousRun`→恢复原始文本→取消跨轮差异 | 失败时不做局部清理，显示 `P09_MEMORY_CLEAR_FAILED001` |

所有写操作携带 `saveRevision`。同一 `actionId` 重放时返回既有结果；较旧版本提交显示 `P09_STATE_CONFLICT001`，不得覆盖较新状态。

## 固定内容与 AI 边界

- 01—07 与 09 的所有 P 编号正文固定；08 中的角色开场、固定话题、拒绝、超时和兜底也固定。
- AI 只为三名角色生成受约束的自由闲聊正文，遵循 `08_角色与对话设定/角色卡与AI提示词.md`。
- AI 不能创建证据、规则、私信、草稿、回答、按钮、状态、结局或上一轮摘要，也不能提议 `PRIVATE_MESSAGE` 事件。
- 模型输出只接受 `message`、`npc{id, emotion}`、`uiEvent`；`uiEvent` 仅可为 `NONE` 或 `GLITCH`。越权或格式错误时整条拒绝，重试一次后采用固定备用回复。

## 组件约定

| 组件 | 主要内容 | 必须保留的操作 |
|---|---|---|
| 问题页 | 问题头、回答列表、普通评论、折叠评论 | 阅读、展开、查看编辑记录、写回答 |
| 私信侧栏 | 用户不存在、宿管阿姨、南楼旧床板 | 固定话题、自由输入、时间详情、返回正文 |
| 规则卡 | 宿管三条规则与六条收集版 | 查看来源；不在 UI 标真假 |
| 调查面板 | C1—C5、截图、编辑历史 | 查看、返回、重复查看；不设全收集门槛 |
| 草稿弹层 | 基础草稿与真实已看插句 | 更新、暂不发布、确认发布 |
| 自己的回答卡 | 发布快照、已登记、更多菜单 | 查看、删除回答；仅当前轮有效 |
| 结局屏 | A/B/C 各三屏与本轮记录 | 继续、查看记录、第三屏后重新进入 |
| 二周目提示 | 上一轮真实行为差异 | 查看/清除上一轮记录；不改当前轮进度 |

## 恢复与降级

- 刷新或真实关闭后恢复同一 `run`、同一回答 ID、当前弹层/结局屏和已提交动作。真实关闭不是 A。
- 网络不可用时显示 `P09_OFFLINE_FIXED_AVAILABLE001`；固定剧情和结局继续可用，自由对话显示 `P09_AI_UNAVAILABLE001`。
- 读取失败优先重试。用户选择“从本轮开头继续”时保留有效 `previousRun`，只重置当前轮；不得自动增加 `run`。
- 存档缺字段使用迁移默认值；历史事实无法证明时写 `unknown`，不能用 `false` 或推断补齐。
- 当前轮回答 ID 无法证明属于本轮时阻止结局，复用 `P06_INVALID_OWN_ANSWER001` 并允许返回问题页。

## 无障碍与演出

数量变化、文本污染、停钟和身份登记均要有可读文本，不只依赖闪烁或颜色。异常演出不遮挡关键按钮，不拦截浏览器原生刷新/关闭，不造成焦点陷阱；系统减少动态效果时直接切换文本状态。
