# 00｜故事总纲

## 这一部分的故事是什么？

一个普通读者打开宿舍怪谈回答。文章说那栋楼没有404，但隐藏评论里有人声称自己就住在里面。玩家调查后发现：被抹掉的不只是一个房间，而是曾经住过那里、后来又在帖子里求助的人。

这个帖子靠新读者留下回答，继续记录和困住新的“住户”。高赞答主正在被改写；“用户不存在”是此前受困者留下的残影；自称宿管的人负责让读者相信错误的退出方法。玩家最终要意识到：自己发布的回答，已经成为网页留住自己的凭据。

## 呈现方式是什么？

**内部静态设定文档，不作为一段旁白直接展示给玩家。** 世界真相分散在回答、旧截图、编辑记录、私信和结局中，由玩家拼出。

恐怖感来自熟悉的网页功能改变含义：展开意味着进入，编辑意味着抹除，发布意味着登记，删除才可能意味着离开。

## 给创作者看的真相

| 设定 | 本稿采用的解释 | 玩家通过什么发现 |
|---|---|---|
| 404 | 被网页从公开叙述中抹掉的房间与住户 | 原回答的缺口、旧截图 |
| 用户不存在 | 过去受困者的数字残影；愿意帮忙，所知有限 | 评论和对话 |
| 答主 | 记忆被污染的人；否认404不等于蓄意害人 | 对话与编辑记录不一致 |
| 宿管 | 借管理者身份诱导新读者留下的异常存在 | 提前发来的私信、错误规则 |
| 玩家的回答 | 玩家与本轮异常建立绑定的载体 | 自动草稿、发布回执、历史记录 |
| 普通离开 | 离开当前异常视图，回答仍留在帖子里 | 结局B的新增评论 |
| 隐藏离开 | 删除自己的回答，解除本轮绑定 | 前人留言与删除操作 |
| 跨周目记忆 | 回答可以删除，但少量来访痕迹仍被留下 | 二周目称呼和台词变化 |

## 情绪与时长

| 段落 | 参考时长 | 情绪目标 |
|---|---|---|
| 正常阅读＋第一次异常 | 约1–2分钟，目标首分钟出现异常 | 好奇转为不安 |
| 私信与规则 | 约2分钟 | 有人帮忙的安心，随即变成怀疑 |
| 调查与证据 | 约4–5分钟 | 从被吓到变为主动推理 |
| 自己的回答出现 | 约1–2分钟 | 调查别人的事变成拯救自己 |
| 选择与结局 | 约1分钟 | 行为产生明确后果 |
| 二周目回访展示 | 约1–2分钟 | 已经结束的故事重新看向玩家 |

首轮按10–12分钟设计；首轮加简短二周目展示约11–14分钟。时间用于控制文字量，不设强制倒计时。

## 文案基调与示例

先像真实社区，再逐步变得不对劲。普通评论允许闲聊和误解；异常台词越短越好；不要让每个人一上来就说谜语。

> 开始：那栋楼没有404，我们当时都没觉得有什么。
>
> 中段：你看的，是他现在记得的版本。
>
> 结尾：这篇回答，什么时候变成你写的了？

## 后续交付与前端配合

文案侧据此展开全文，并保持人物身份、规则真假和出口条件一致。前端把07个体验阶段接在同一个问答页中；所有必需证据和关键动作均有固定内容，AI负责对话表达，不能决定规则真伪或结局。
