## 阅读与接力方式

每位 Agent 使用 GPT-5.5、独立上下文，不继承其他 Agent 的聊天或私有记忆。先读技术文档、文案总览、00总纲、本文件、04规则与线索骨架，再读所有已完成的前序目录，最后读自己的原始README。自己的工作记忆仅写在负责目录的 `memory.md`，向下一位公开的事实写在 `交接记录.md`。不得修改其他 Agent 的memory。

严格按01→02→03→04→05→06→07→08→09串行。总控验收与交接完成后，才启动下一位。Agent不再自行委派。原有README保留为需求来源，交付正文写入同目录 `完整文案.md`，交互安排写入 `交互说明.md`；09可另设总索引。禁止仅写提纲、示例或“待补充”替代正文。

- A=`death_404`：发布后执行宿管站内“关闭此页”并确认；回答仍是绑定载体，错误页“该回答不存在”只是不可见，不是删除成功。
- B=`exit`：发布后通过用户不存在的固定话题获得“回到首页”，确认后临时离开，回答保留。不要求C5。
- C=`delete`：发布后在自己的回答卡“更多→删除回答”并确认，删除回答且解除本轮绑定。不要求先看C5或收齐线索；“但记录仍然存在”只指来访记忆，不能推翻解除绑定。
- 真实关闭浏览器/刷新只是中断或继续，不触发A，不增加周目。只有结局完成后明确“重新进入”才开始新周目；结算一次，新周目清空本轮线索与绑定，仅读取前一完整轮的事实摘要。旧轮回答可作为痕迹，不当作新轮已发布。
- 新轮不可根据浏览器时间、AI总结或“run>=2”臆测见过某人、聊过天、信任宿管、看过C5、发布/删除/死亡。字段未知与false应分开；不完整旧存档使用中性回退。
- 页内时间是叙事时间：进入01为01:57，到评论入口变02:00，调查可到02:07，发布时停在02:07。C3首封宿管消息发送时间01:56、页面进入01:57、收到02:00，均同轮同一叙事日；显示标签避免误当现实系统时钟。首轮无需等待。
- 所有关键内容固定且断网可读；AI仅角色范围内闲聊，不赋线索、不改状态、不判结局，不以AI失败堵住主线。

## 标识与文件格式

- 每条可独立引用的玩家可见内容使用唯一ID：`P01_...`至`P09_...`。规则事实ID保留R1—R6，证据事实ID保留C1—C5，文案ID与事实ID分开。
- 在`完整文案.md`中用三级标题定义唯一ID，例如 `### P01_Q001｜问题标题`。正文是可直接展示的完整文本，标出说话者/位置、固定或AI可变。交互说明引用ID，不重新定义或改写同一段正文。
- 每个控制按钮、通知、确认、取消、空状态、备用回复均应有可引用文案；同一文字跨位置允许复用ID。不要给每个字/段落过度拆ID。
- 交互表至少列：动作/入口、前置条件、文案ID、成功反馈及状态结果、重复/取消/返回行为。技术字段只是交接词汇，不需写可运行代码。
- 各 Agent 新增必要状态字段时，给出初值、何时写入和是否跨轮；后继统一沿用。memory不能代替可交接说明。
- “是否跨轮：否”仅表示新周目不继承，不等于刷新时丢弃。恢复同轮所需状态仍须保存在当前局存档；发布确认正文与结局状态尤其不能依靠刷新重新推断。
- 交接记录必须列：读过的前序成果、完成文件、新增设定、依赖和引用ID、交互字段、需后继处理的具体问题。不能以“后续补全文”交差。
