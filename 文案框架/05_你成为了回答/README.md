# 05｜你成为了回答：故事开始使用“我”

## 这一部分的故事是什么？

调查进行到一半，页面出现“你有一篇未发布的回答”。打开后，玩家发现正文记录了自己刚才展开评论、查看私信的经历，但把这一切写成了“我住进404那晚”的回忆。

宿管说发布说明就能办理离开；用户不存在提醒玩家先看清它写了什么。玩家发布后，页面显示“已登记”，玩家的身份与这个故事正式绑定。此前的调查突然有了切身后果。

这是隐藏结局的必要铺垫：玩家必须知道哪一篇是自己的回答，之后删除它才是一种有依据的行动。

## 呈现方式是什么？

**点击查看草稿＋明确的发布操作＋局部页面文字变化。**

1. 查看C2或C4后出现草稿提示。
2. 草稿用预写句子拼接玩家实际完成过的操作。
3. 玩家可以“发布回答”，也可“暂不发布，继续查看记录”。
4. 发布后，正文区出现署名“你”的回答卡，保留“更多”菜单。
5. 页内时间停住，宿管发来关闭指令，三个结局入口准备就绪。

“暂不发布”返回调查，稍后仍可从“我的草稿”继续。第一版完整结局线以发布为共同前置，不把它伪装成无关的装饰按钮。

## 关键示例

草稿提示：

> 你有一篇未发布的回答。

草稿开头：

> 我以前也不相信有404。
> 直到凌晨两点，我展开了第十八条评论。

如果玩家确实读过私信，再追加：

> 宿管比我先知道，我会住进来。

宿管：

> 把情况写清楚，发出来，我给你办离开。

发布后的回执：

> 回答已发布。
> 四楼住户已登记。

## 玩家动作与推进

发布是固定游戏动作，不调用AI判断是否成功。只有发布成功后，才开启最终关闭、返回首页和删除回答的结局路径。发布前后都可回看证据，不设“看慢了就死”的倒计时。

## 你后续要写什么？

1篇基础草稿、3–4条按实际行为插入的句子、草稿提示、发布按钮、暂缓按钮、发布回执、宿管催促与用户不存在的提醒。

## 前端同学需要做什么？

复用回答卡与简单草稿弹层，不必实现完整富文本编辑器。给玩家自己的回答明确署名，并在“更多”里保留“删除回答”；删除入口在结尾仍然可操作，不能被异常效果遮住。
