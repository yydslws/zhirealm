# 05｜你成为了回答：交互说明

本阶段承接 04 的草稿开放状态。玩家查看草稿、暂缓、取消都不会绑定身份；只有玩家在确认框里点击“确认发布”，才新增署名“你”的唯一回答卡，并写入已登记、停止页内时间、提升污染和开放 06 结局入口。

## 承接状态

| 来自前序的状态 | 需要满足的值 | 05 的处理 |
|---|---:|---|
| `gameTime` | `02:07` | 查看草稿和暂缓时保持 `02:07`；发布成功后仍显示 `02:07`，同时 `timeStopped=true` |
| `timeStopped` | `false` | 发布前必须保持 `false`；只有发布成功后改为 `true` |
| `pollution` | `2` | 发布前保持 `2`；发布成功后提升到 `3` |
| `draftAvailable` | `true` | 仅当玩家实际看过 `C2` 或 `C4` 后由 04 写入；05 不自行补开 |
| `phase05Available` | `true` | 与 `draftAvailable` 同源；点击草稿不再要求额外门槛 |
| `draftUnlockedBy` | `C2` 或 `C4` | 只记录首次开放来源；不决定草稿最终包含哪些句子 |
| `hasSeenC2` / `hasSeenC4` | 至少一个为 `true` | 用于决定草稿核心插句；没有看过的证据不得出现在草稿正文 |
| `hasSeenC3` / `hasSeenC5` | 任意 | 只有为 `true` 时才加入对应插句 |
| `hasRepliedUser404` / `hasChattedDormManager` / `hasAskedAuthorInP04` | 任意 | 05 草稿不写聊天经历；这些字段留给 07 的二周目记忆使用，不能在 05 写成信任或阵营选择 |

04 总控验收补充优先生效：必须实际展示 C2 或 C4 正文后，`draftAvailable` 与 `phase05Available` 才能同时为 `true`。只看 C1、C3、规则卡、对照列表或 NPC 回复，都不能开放 05。

## 新增状态字段

| 字段 | 初值 | 写入时机 | 是否跨轮 |
|---|---:|---|---|
| `p05DraftOpen` | `false` | 点击草稿入口后改为 `true`；关闭或返回调查后改为 `false` | 否 |
| `draftSnapshotId` | `null` | 每次打开草稿时生成一次本轮快照 ID；取消后可在下次打开时生成新快照 | 否 |
| `draftSnapshotClues` | `[]` | 打开草稿时复制当时已经实际看过的 `C1`—`C5` | 否 |
| `draftSnapshotActions` | `{}` | 打开草稿时复制当时已经发生的聊天、询问、查看行为 | 否 |
| `draftPreviewText` | `null` | 按打开草稿时的快照拼接 `P05_DRAFT_BASE001` 与可用插句 | 否 |
| `publishConfirmOpen` | `false` | 点击 `P05_CTRL_PUBLISH001` 后改为 `true`；确认或取消后改回 `false` | 否 |
| `publishSnapshotText` | `null` | 打开发布确认时复制当前玩家看见的草稿正文 | 本轮内保存 |
| `hasPublishedOwnAnswer` | `false` | 玩家明确确认发布且成功后改为 `true` | 结局结算时写入跨轮摘要 |
| `ownAnswerId` | `null` | 发布成功时创建唯一的本轮“你”的回答卡 ID | 本轮内保存；结局结算可摘要 |
| `ownAnswerText` | `null` | 发布成功时写入 `publishSnapshotText`，必须与确认框正文一致 | 本轮内保存；结局结算可摘要 |
| `ownAnswerRegistered` | `false` | 发布成功时改为 `true` | 本轮内保存 |
| `p05IdentityShiftShown` | `false` | 发布成功后展示身份异变提示时改为 `true` | 本轮内保存 |
| `phase06Available` | `false` | 发布成功后改为 `true` | 本轮内保存 |
| `p05DormPushBeforeShown` | `false` | 发布前宿管催促首次出现时改为 `true` | 本轮内保存 |
| `p05User404WarningBeforeShown` | `false` | 发布前用户不存在提醒首次出现时改为 `true` | 本轮内保存 |

跨轮摘要仍只在 06 的结局完成时统一写入。真实刷新、真实关闭浏览器、重复打开草稿或取消发布都不是结局，不增加周目。

## 草稿拼接规则

草稿正文由固定片段拼接，不调用 AI。05 只使用 4 条证据型插句，避免把聊天、信任或阵营选择误写进玩家回答。排序固定如下：

| 顺序 | 文案 ID | 精确条件 | 快照说明 |
|---:|---|---|---|
| 1 | `P05_DRAFT_BASE001` | `draftAvailable=true` 且玩家打开草稿 | 每次打开草稿都包含；基础正文只写玩家必经的阅读、展开第 18 条和进入调查，不写 C3、C5、聊天或发布 |
| 2 | `P05_DRAFT_INSERT_C2001` | 草稿打开快照中 `hasSeenC2=true` | 只有实际展示过 C2 旧截图正文才加入；只看旧截图入口不加入 |
| 3 | `P05_DRAFT_INSERT_C4001` | 草稿打开快照中 `hasSeenC4=true` | 只有实际展示过 C4 五次编辑记录才加入；只看编辑记录元信息不加入 |
| 4 | `P05_DRAFT_INSERT_C3001` | 草稿打开快照中 `hasSeenC3=true` | 只有实际打开宿管消息详情并渲染 `P03_MESSAGE_DETAIL_DORM001` 后才加入 |
| 5 | `P05_DRAFT_INSERT_C5001` | 草稿打开快照中 `hasSeenC5=true` | 只有实际打开 C5 旧评论后才加入；首轮可加入，但不能写成玩家上一轮留言 |
| — | `P05_DRAFT_FOOTER001` | 草稿弹层未发布时 | 仅为界面状态，不拼入正文、发布快照或已发布回答 |

如果玩家打开草稿后返回 04，又查看了新证据，当前已打开的草稿不自动变文。玩家再次打开草稿或点击 `P05_CTRL_REFRESH_DRAFT001` 时，重新取一次快照并更新 `draftPreviewText`。打开发布确认后，`publishSnapshotText` 冻结；确认发布必须使用该冻结文本，保证确认时看见的正文和发布后的 `ownAnswerText` 完全一致。

| 动作 / 入口 | 前置条件 | 文案 ID | 成功反馈及状态结果 | 取消 / 重复 / 返回行为 |
|---|---|---|---|---|
| 草稿开放提示出现 | 04 实际展示 C2 或 C4 后，`draftAvailable=true` 与 `phase05Available=true` | `P05_DRAFT_NOTICE001`、`P05_DRAFT_NOTICE_DETAIL001`，可复用 `P04_TOAST_DRAFT_AVAILABLE001`、`P04_NEXT_PHASE_HINT001` | “写回答”入口切换为可打开草稿；`gameTime=02:07`，`timeStopped=false` | 只提示一次；返回调查后入口保留 |

## 发布后的页面结构

发布成功后，问答页至少保留两张回答卡：

| 顺序 | 回答卡 | 内容来源 | 操作 |
|---:|---|---|---|
| 1 | “南楼旧床板”的原高赞回答 | 01 的 `P01_ANSWER001` 与 `P01_ANSWER_TAIL001`，仍为第 5 次编辑版本 | 可回看、可进编辑记录 |
| 2 | 署名“你”的回答 | 发布确认时冻结的 `publishSnapshotText`，元信息用 `P05_MY_ANSWER_META001` | `P05_CTRL_MORE_MY_ANSWER001` 一直可用，含 `P05_CTRL_DELETE_MY_ANSWER001` |

“你”的回答是本轮绑定载体。05 只负责创建并登记它；06 负责玩家后续选择关闭、回首页或删除。隐藏结局不能被 C5 门槛锁住：发布后自己的删除入口始终存在，知道答案的玩家可以直接操作。

## AI 与断网约束

- 草稿拼接、发布确认、发布回执、身份异变、宿管催促和用户不存在提醒都使用固定文案，断网可用。
- AI 可以用于 NPC 自由输入的语气变化，但不能改写草稿正文、不能决定是否发布成功、不能创建多篇回答、不能判定结局。
- 发布成功由固定动作推进，不由 AI 判断玩家是否“愿意”“信任宿管”或“理解出口”。
- 玩家可见正文不显示 `draftAvailable`、`phase05Available`、`timeStopped` 等状态字段；这些只在交互说明和前端实现中使用。

## 总控验收补充

发布一次性写入ownAnswerId、ownAnswerText、hasPublishedOwnAnswer、ownAnswerRegistered、timeStopped、pollution与phase06Available；失败不得留下半张已登记回答。成功后关闭草稿和确认框；之后草稿入口只定位已发布回答。问题回答数118变119，展示P05_QUESTION_ANSWER_COUNT001；重复确认不加数，高赞答主评论仍25。新增p05DormPushAfterShown与p05User404WarningAfterShown，初值false，本轮保存，发布后对应消息展示时置true，与发布前标志独立。刷新未确认的发布框不自动发布。

## 与06的回答归属约定

新轮ownAnswerRunId=null、ownAnswerVisible=false、ownAnswerBindingActive=false、ownAnswerDeleted=false。05发布成功时同时写ownAnswerRunId=run、ownAnswerVisible=true、ownAnswerBindingActive=true，并令ownAnswerRegistered=true；这些必须与回答创建一起保存。旧存档缺少归属信息时，不直接把旧回答认作当前轮回答，交07按恢复规则处理。
