# 06｜三个结局：交互说明

本阶段承接 05 发布成功后的状态。三个结局都必须满足同一共同前置：`hasPublishedOwnAnswer=true`、`ownAnswerRegistered=true`、`ownAnswerId` 指向当前周目的那张署名“你”的回答卡，且本轮尚未结算。发布前没有三种出口；聊天、阅读规则、看宿管私信、真实关闭浏览器或刷新都不算选择。

## 承接状态

| 来自前序的状态 | 需要满足的值 | 06 的处理 |
|---|---:|---|
| `hasPublishedOwnAnswer` | `true` | 三个结局入口共同前置；否则显示 `P06_LOCKED_BEFORE_PUBLISH001` |
| `ownAnswerRegistered` | `true` | 表示本轮回答已登记；A/B 会保留，C 会删除并解除登记绑定 |
| `ownAnswerId` | 当前周目有效 ID | 必须能定位到本轮署名“你”的回答卡；无效时显示 `P06_INVALID_OWN_ANSWER001` |
| `ownAnswerText` | 发布确认时冻结的正文 | 仅用于本轮已发布回答显示；结局摘要不保存回答全文 |
| `timeStopped` | `true` | 06 显示时间停止后的入口；页面时间保持 `02:07` |
| `gameTime` | `02:07` | 结局完成时写入 `completedAtGameTime=02:07` |
| `pollution` | `3` | 结局演出期间保持；新周目由 07 重置本轮状态 |
| `phase06Available` | `true` | 开放宿管关闭、用户不存在回首页话题和自己的回答菜单 |
| `p05DormPushAfterShown` / `p05User404WarningAfterShown` | 任意 | 只决定对应提醒是否已展示；不作为结局门槛 |

`ownAnswerId` 的“本轮有效”建议判定为：存在非空 ID；该 ID 对应的回答卡作者为“你”；回答卡创建于当前 `run`；`ownAnswerRegistered=true`；`ownAnswerDeleted=false`；`endingSettled=false`。回答周目归属应在 05 发布成功时写入；如果旧存档缺少 `ownAnswerRunId` 或无法证明 ID 属于本轮，不得由 06 补写成当前 `run`。

三结局互斥：`endingSettled=true` 后，任何结局入口、确认按钮、重复点击或延迟回调都只显示 `P06_ALREADY_SETTLED001` 或当前结局屏，不得覆盖 `endingId`，不得追加第二次自动评论，不能再次删除或关闭。

## 结局事件

| 事件 ID | 触发动作 | 结果 |
|---|---|---|
| `ending_event_death_404` | 宿管站内“关闭此页”确认成功 | 写入 `endingId=death_404`；回答保留但对玩家不可见；绑定仍有效 |
| `ending_event_exit` | 用户不存在固定话题给出“回到首页”后，玩家确认回首页 | 写入 `endingId=exit`；回答保留，绑定仍有效；在“你”的回答卡下添加 1 条页面自动评论 |
| `ending_event_delete` | 自己的回答卡“更多→删除回答”确认成功 | 写入 `endingId=delete`；真实删除本轮回答；解除本轮绑定 |

事件由固定按钮确认触发。AI 回复、自由聊天、NPC 语气变化、读完证据或污染值变化都不能触发结局。

## B 结局评论与计数

B 的新增评论是页面自动事件，落在 05 创建的署名“你”的回答卡下方，不是玩家主动发送，也不写入 `conversationHistory` 的玩家消息。

计数固定为：

| 位置 | B 结局后显示 |
|---|---:|
| 问题回答数 | 119 个回答 |
| “南楼旧床板”高赞回答评论数 | 25 |
| 署名“你”的回答评论数 | 1 |

如果玩家刷新 B 结局页，`bAutoCommentAdded=true` 时只恢复同一条自动评论，不追加第二条。

## 结局事实摘要

06 在任一结局确认成功、状态写入完成的同一刻，一次性写入精简 `previousRun`。07 只能根据这些真实字段写二周目，不得把 NPC 自由闲聊摘要、AI 生成句子或未初始化字段当成历史。`previousRun` 不保存玩家回答全文；尤其 C 删除后，只保留删除事实、结局和少量行为标记，不能把已删除回答的正文塞进摘要再重建。

建议结构：

| 字段 | 写入规则 |
|---|---|
| `previousRun.run` | 当前 `run` |
| `previousRun.completed` | 结局确认成功后写 `true` |
| `previousRun.endingId` | `death_404` / `exit` / `delete` |
| `previousRun.endingEventId` | 对应 `ending_event_*` |
| `previousRun.completedAtGameTime` | 固定写 `02:07` |
| `previousRun.hasPublishedOwnAnswer` | 由当前 `hasPublishedOwnAnswer` 写入，三结局应为 `true` |
| `previousRun.ownAnswerId` | A/B 可写当前周目的 `ownAnswerId` 作为残留痕迹定位；C 写 `null`，避免用已删除 ID 重建回答 |
| `previousRun.ownAnswerWasRegistered` | A/B 写 `true`；C 写 `false`，表示删除结算后本轮登记已解除 |
| `previousRun.ownAnswerDeleted` | A/B 写 `false`；C 写 `true` |
| `previousRun.ownAnswerRetainedAfterEnding` | A/B 写 `true`；C 写 `false` |
| `previousRun.ownAnswerBindingActiveAfterEnding` | A/B 写 `true`；C 写 `false` |
| `previousRun.usedDormClose` | 只有 A 写 `true`；B/C 写 `false` |
| `previousRun.usedUser404HomeReturn` | 只有 B 写 `true`；A/C 写 `false` |
| `previousRun.usedOwnAnswerDelete` | 只有 C 写 `true`；A/B 写 `false` |
| `previousRun.bAutoCommentAdded` | 只有 B 写 `true`；A/C 写 `false` |
| `previousRun.bAutoCommentText` | B 写 `P06_B_AUTO_COMMENT001` 的正文；A/C 写 `null` |
| `previousRun.metUser404Seen` | 从 `hasSeenUser404Comment` 原样复制；缺失写 `unknown` |
| `previousRun.user404Replied` | 从 `hasRepliedUser404` 原样复制；缺失写 `unknown` |
| `previousRun.hasSeenDormOpening` | 若本轮字段存在，照实写入；缺失写 `unknown` |
| `previousRun.hasChattedDormManager` | 若本轮字段存在，照实写入；缺失写 `unknown` |
| `previousRun.hasSeenC2` / `hasSeenC3` / `hasSeenC4` / `hasSeenC5` | 各自只按本轮真实字段写入；缺失写 `unknown` |
| `previousRun.draftUnlockedBy` | 当前字段存在则照写；缺失写 `unknown` |
| `previousRun.firstTopic` 字段组 | 只保存前序已定义的枚举值；没有或缺失写 `unknown` |

`false` 只表示本轮明确没有发生；字段不存在、旧存档缺项或读取失败时写 `unknown`。07 遇到 `unknown` 时使用中性回访文案，不能补成“你上次见过/相信过/删除过”。

## AI 与断网约束

- 三结局触发、确认、取消、收束、记录、重新进入全部使用固定文案，断网可用。
- AI 可以继续处理 NPC 自由闲聊，但不能提供新的结局条件、不能判定玩家相信谁、不能宣布死亡、不能删除回答、不能创建或清除跨轮摘要。
- 用户不存在在 06 只知道临时回首页方法，不能说出删除自己的回答才是彻底出口。
- 宿管只能引导站内关闭入口，不能把真实浏览器关闭解释成成功离开。

## 总控验收补充

三个确认动作都先检查endingActionLock=false且endingSettled=false，再一次性提交结果；成功时p06ConfirmOpen=null、endingScreenIndex=1、scene=ending。失败不写部分结局，释放锁并保留原回答，复用P05_PUBLISH_INCOMPLETE_TOAST001不适合关闭/删除，交09提供通用操作失败反馈。A/B保留ownAnswerRegistered=true；C写false并移除活动回答卡、清正文与草稿副本。C当前ownAnswerId可保留为不可渲染的删除记录标识，仅用于结算摘要，新周目必须清空。C问题回答计数固定回到118，结局演出可隐藏计数，但不改变该结果。

firstTopic字段组精确定义：user404取user404FirstReplyKind，dormManager取dormManagerFirstTopic，author取authorFirstP04Topic；阶段补充可用user404P03/user404P04/dormP04，对应前序同名FirstTopic字段。源字段明确null表示尚未发生，保留null；字段不存在写unknown。未发送对话只读角色开场，不创建任何firstTopic。hasAskedAuthorInP04也须原样存入previousRun，以供07区别见过答主和与其交谈。
