# 06｜三个结局：什么才算离开？

## 这一部分的故事是什么？

玩家面对的不是突然弹出的三道选择题，而是网页中三种已经铺垫过的操作：按宿管指示关闭、跟随证人的提示返回首页、删除自己刚刚发布的回答。每种行为表达玩家对现有证据的不同理解。

## 呈现方式是什么？

**网页控件上的分支交互＋短文本静态收束。** 结局文字可以分两步出现，不需要长篇旁白或新场景。

### A｜404：你也被留下了

**故事**：玩家按宿管的错误指引执行“关闭此页”，自己的回答没有消失，消失的是自己。

**触发**：已发布回答、时间停住后，点击宿管消息提供的“关闭此页”，确认“按管理规定离开”。这是游戏页面内的操作。

**演出**：问答主体变为错误页，第一句随后替换为第二句。

> 404｜该回答不存在。
>
> 该用户不存在。

结局内部标识：`death_404`。文案意图是让玩家意识到自己成为了“用户不存在”的同类。

### B｜退出：你出去了，回答还在

**故事**：用户不存在只能帮助玩家离开当前异常页面。他不知道如何彻底解除绑定。

**触发**：发布回答后，通过用户不存在固定提供的“怎样离开这里？”话题，获得“回到首页”的入口并点击。不要求先获得C5。

**演出**：先显示“页面加载失败”，再恢复站内正常首页摘要；玩家自己的回答下增加一条自动评论。

> 有人知道刚才发生什么了吗？

结局内部标识建议：`exit`。这是一种暂时逃脱，保留“我的回答仍存在”的后患，与隐藏结局区分。

### C｜删除：解除本轮绑定

**故事**：玩家根据旧记录推断，网页通过自己的回答保留身份。删除这篇回答，才会解除本轮绑定。

**触发**：发布回答后，在署名“你”的回答卡中选择“更多 → 删除回答”，确认删除。无需先打开所有证据卡，避免把推理变成收集门槛。

**演出**：玩家回答消失，页面逐步清空，最后两行依次出现。

> 内容已删除。
>
> 但记录仍然存在。

结局内部标识建议：`delete`。第二句指向跨周目来访痕迹，不能暗示删除其实完全无效。

## 共同的收束与重来

结局完成后显示“重新进入”与“查看本轮记录”。重来时保存本轮结局及少量真实行为，进入07。删除确认中的“取消”回到当前页面，不触发结局。

玩家关闭真实浏览器标签页不作为死亡判定。回来后按存档继续；不用拦截浏览器退出制造恐怖。

## 你后续要写什么？

每个结局一组触发前提示、一组确认与取消文案、两到三屏短句、重来按钮；总共三个结局，不扩写大量细分死亡故事。

## 前端同学需要做什么？

三个明确的结局条件、一次性结算、结局状态替换与存档。AI聊天不能直接宣布死亡、替玩家发布或替玩家删除。
